## 1. 这是什么 / 适用与不适用场景

### 两条主线

| 主线 | 你手上的文稿 | 这个 skill 做什么 | 是否改原件 |
|---|---|---|---|
| **核实（Verify）** | 已经有引用（Zotero 活引用或手写 `[1]`） | 只读核对：正文引用 ↔ 文末列表一一对应、去重、顺序、格式；检查域代码/URI/残留占位符/著录缺陷/证据强度；出核对报告 | **否** |
| **导入（Import）** | 用 `[REF:key]` 占位符标了「这里要引」 | 把占位符换成 Zotero Word 插件能识别、能 `Refresh` 的**域活引用**，并在文末生成去重参考文献列表 | 是（只替换占位符、末尾加书目） |

两者可串联：**先导入 → 再核实 → 最后独立审核收口**。

### 「活引用」是什么（大白话）

- **死引用**：把 `[1]` 当文字打上去。以后在 Zotero 里改了资料，Word 里不会跟着变。
- **活引用**：插入的是「带芯片的引用」——每个引用记住自己对应 Zotero 里哪一条文献。以后改了文献信息、或在 Word 点一下 `Refresh`，编号和文末清单会自动重排更新。

### 适用

- 载体是 **Microsoft Word / WPS 的 `.docx`**，且装有 **Zotero 桌面端 + Zotero Word 插件**。
- Zotero 10.x，本机 **Local API 已启用**、桌面端运行中。
- 想把本地 Zotero 库的条目挂进文稿，或想核对已有引用的一致性。
- 完全**离线**工作，不需要联网、不需要 API key。脚本只读取 Zotero Local API，不修改 Zotero 文献库，也不读取任何凭据。

### 不适用（如实说明，别硬套）

| 场景 | 为什么不行 |
|---|---|
| 纯 LaTeX / `.tex`、Markdown、Google Docs、网页 | Zotero 的「域代码」是 Word/OOXML 特有的，本 skill 只写 `.docx` 里的域 |
| 只想在线检索文献、下载 PDF | 本 skill 不检索、不下载；请用 Zotero 本身或检索类工具 |
| 想让 AI **全自动**完成最后验收、不碰 Word | 做不到：官方本地 API 没有「写 Word 域 / 刷新文档」的端点，最后一步必须人在 Word 里点 `Refresh`（见 §9） |
| 需要把 CSL 样式文件一起分发 | 不打包（许可证不确定），只用你本机已安装的样式 |

## 2. 3 步快速开始

> 前提：Zotero 运行中、Word 装好了 Zotero 插件、Python 装好了 `lxml`。

**第 1 步｜放好 skill**
把 `zotero-ref-verify-import/` 整个目录放进 Codex 用户级 skills 目录：

- Windows：`%USERPROFILE%\.codex\skills\zotero-ref-verify-import`
- macOS / Linux：`~/.codex/skills/zotero-ref-verify-import`

也可以把本目录放进项目的 `.agents/skills/`，或直接作为参考手册使用。

**第 2 步｜填配置**
复制 `assets/config.example.json` 为 `assets/config.json`，把所有 `<...>` 占位符换成你的真实值：文稿路径、Python 解释器、Zotero 库 id、样式名、映射表等（详见 §6）。
> 格式/样式这一项**先别自己定死** —— 见 §8，执行前要问一次使用者。

**第 3 步｜先探险、再动手**
```bash
# 只读基线（核实主线的第一步，绝不写文件）
python scripts/zotero_citation.py --config assets/config.json inspect

# 导入主线：先看 dry-run 计划（不写文件），确认后再加 --apply
python scripts/zotero_citation.py --config assets/config.json build            # dry-run
python scripts/zotero_citation.py --config assets/config.json build --probe --apply   # 最小探针
# 在 Word 里对探针执行 Document Preferences + Refresh 验证「活域能被认出来」
python scripts/zotero_citation.py --config assets/config.json build --apply   # 全量
```

**强烈建议**：第一次一定走「最小探针 + 你在 Word 里刷新一次」这条路（§7 S4）。探针能认出来，再全量；认不出来立刻停，别硬改。

## 3. 能力总览（核实 / 导入 / 审核）

### 三个动作 ↔ 脚本子命令

| 动作 | 子命令 | 读写 | 输出 |
|---|---|---|---|
| **核实 · 基线** | `inspect` | 只读 | API 连通、包结构、占位符数、映射覆盖率、样式渲染实测 |
| **核实 · 预填态自校** | `verify` | 只读 | 生成后、刷新前的严格静态自校（5 项） |
| **核实 · 成品态诊断** | `diagnose` | 只读 | 刷新之后的结构诊断（域计数/上标/著录段/URI），不会误报 |
| **核实 · 素材** | `material` | 只读 | dump 著录全文 + 编号表 + 存疑候选段落 |
| **导入 · 生成** | `build` | 写（需 `--apply`） | 预填态活文档；`--probe` 只做 1 个引文域 |
| **审核** | 多子 agent + 独立收口 | 只读 | 一一对应/去重/顺序/格式 + 证据分级 + 缺陷加注（§10 交付物 4） |

> `inspect / verify / diagnose / material` 全程只读；只有 `build --apply` 会写文件，默认 `dry-run` 只打印计划。这个设计就是为了让「核实」可以放心跑。

### 可进阶分级 L1 → L4

| 层 | 能力 | 何时用 |
|---|---|---|
| **L1 基础导入** | 占位符 → N 个 ITEM 域 + 1 个 BIBL 域 + 去重著录 | 只想把引用挂上 |
| **L1' 基础核实** | 只读核对已有引用 | 引用已存在，只想查对 |
| **L2 元数据与样式** | 补全条目非 title 字段、样式差异对照 | 库里有条目元数据为空 |
| **L3 审核与多 agent 收口** | 证据分级、四项交付物、独立审核 | 正式交付、要出审核报告 |
| **L4 跨项目复用** | 全配置外置、默认规则、弯路开关 | 换项目只换 `config.json` 即可跑 |

## 6. 配置说明（config.json 逐字段）

复制 `assets/config.example.json` → `assets/config.json`，按下表填写。**所有路径用绝对路径。**

| 字段 | 必填 | 含义 / 怎么填 |
|---|---|---|
| `python` | 建议 | Python 解释器绝对路径（受控 venv），勿用裸 `python` |
| `source_docx` | ✅ | 原稿 `.docx` 绝对路径（**全程只读**） |
| `deliver_docx` | ✅ | 交付活文档输出路径 |
| `verify_copy_docx` | 否 | 验证副本路径（探针/真机验证用），留空则不生成 |
| `api_base` | ✅ | 本地 API 基址，默认 `http://127.0.0.1:23119` |
| `user_id` | 否(默认0) | 本机 **library id**。用 `GET /api/users/<id>/items?limit=1&format=json` 返回的 `library` 对象确认，勿凭印象 |
| `style` | ✅ | 本机已安装样式名（不含 `.csl`）。**属决策门 D0，执行前先问** |
| `language` | 否 | `zh` / `en`，用于默认样式建议 |
| `cid_prefix` | 否(默认`CITE`) | citationID 前缀，任意标识，**勿用真实项目缩写** |
| `sentence_end` | 否(默认`。`) | 句末标点。中文 `。`，英文 `.`（影响插入点定位） |
| `title_verbatim` | 否(默认`false`) | `true`=著录缺陷原样保留不润色；`false`=按体例规范化。见 §11 C5 |
| `citation_plan` | ✅ | 编号表，见下 |
| `key_to_itemkey` | ✅ | `REF 键 → Zotero itemKey` 映射 |
| `doubt_paras` | 否 | 无占位符但需文献支撑的段落号，仅登记存疑 |
| `high_risk_cids` | 否 | 证据偏弱引用点的 cid，列入存疑清单最高风险 |
| `evidence` | 否 | 处级/键级证据统计（数值由你的证据核验材料填） |

### `citation_plan` 每行字段

```json
{"para": 5, "seq": 1, "num": 1, "key": "REF-EXAMPLE-A", "itemkey": "ITEMKEY01", "cid": "C01"}
```
- `para`：占位符所在段号（1-based，body 直属段落）
- `seq`：引用点序号（每处递增）
- `num`：著录编号；**同一文献多次引用复用同一 `num`**
- `key`：`[REF:key]` 里的键
- `itemkey`：Zotero 条目 key（8 位）
- `cid`：审计 ID（用于证据分级/存疑清单）

> **不要手猜编号表**：由 §7 的 S2（映射）+ S3（定位）生成，`inspect` 会自动比对「实定位 vs 编号表」是否一致。

### 占位符规范 `[REF:key]`

- 写在待引论述**之后**（常见形态 `……论述。[REF:key]`）；脚本会把引用域插到句末标点**之前**（`……论述[1]。`）。
- `key` 只允许 `[A-Za-z0-9-]`，且必须在 `key_to_itemkey` 里有对应 itemKey。
- 没有占位符的段落**不会**被新增引用点，只会登记到 `doubt_paras` 供人工判断（对应默认约定 C3）。

## 7. 完整工作流 S1–S7

> 顺序不可换；每步都遵循「先建地图 → 按需取用 → 每步留痕」。详细版见 `references/workflow.md`。

| 步 | 动作 | 输出 / 验收 |
|---|---|---|
| **S1 基线** | 绕代理连本地只读 API、样式渲染确认、docx 包结构与占位符定位（先 grep 建地图，不通读） | 基线表：无锁、无 custom.xml、无既存域；占位符数 |
| **S2 映射** | 锁定 `REF 键 → itemKey → 编号`，从 API 取真实 `itemData` / `uris` | 编号表 + 可核验 itemKey |
| **S3 定位** | 只读定位占位符段落/run/句末标点，登记无占位符候选段落 | 定位片段 + 存疑候选 |
| **S4 最小探针** | 1 引文域 + 1 书目域 → 静态自校 → **用户在 Word 手动设样式并 Refresh 一次接管** | 失败即硬停止，不退化、不写库 |
| **S5 全量注入** | N 个 ITEM 域 + 跨段落 BIBL 域 + 去重著录 → 严格静态自校（5 项） | 仅 `word/document.xml` 变化；citationID 全唯一 |
| **S6 定稿** | Word 中 `Document Preferences` + `Refresh` | 标注形态/位置、编号连续、书目条数、无「引用已被修改」 |
| **S7 交付** | 四项交付物 + 独立审核汇总（审核不参与写入） | 一一对应/去重/顺序/格式全通过 |

**走「核实」主线时**：跳过 S4/S5 的写入，用 `inspect → verify/diagnose → material → 独立审核` 产出只读核对报告，原件零改动。

### 执行前必须先问的决策门（摘要，完整见 workflow.md §0）

D0 格式/样式 · D1 编码制/列表位置 · D2 交付形态 · D3 标注形态 · D4 是否只处理占位符 · D5 弱证据引用点是否插入 · D6 是否授权补元数据/装样式 · D7 是否授权写 `custom.xml` · D8 Refresh 失败如何处置。

> 全部是**默认建议**，用户/使用者可逐项调整；调整后写进执行卡并等批准。

## 8. 引用格式默认规则（决策门 D0）

「该用哪种引用格式/样式」属于**选项判断**，执行前**必须先问使用者**，不能凭默认值擅自定。

- **默认起点（仅建议/兜底，不是授权）**：按**文章语言**判定 —— 中文文章默认 `GB/T 7714` 顺序编码制；英文文章默认 `APA 7`。
- 按**文章语言**，不按被引文献语言（中文稿引英文文献仍用 7714）。
- 提问时把默认值作为推荐项给出，确认后再锁定 `config.style`。
- 若项目自带体例文件与默认冲突：**以项目文件为准并明示差异**，仍请使用者裁决。

> 数字顺序编码样式 Refresh 后引文会变成**上标** `[n]`（样式 `vertical-align="sup"` 决定），这是正常渲染、不是文档损坏。规划期就实测并写进验收基线，别事后去「修」上标（`pitfalls.md` P5）。
>
> 另：「默认采用某样式」与「合规免责」是两个层面，不矛盾。若著录确有抽取缺陷或体例文件未标标准号，别删免责句，否则会造出「宣称合规却有缺陷」的新矛盾。

## 9. 验收：自动自校 vs 必须人工在 Word 刷新

### 9.1 先分清：哪些能自动、哪些必须人工

| 部分 | 由谁做 | 能否自动化 | 作用 |
|---|---|---|---|
| 静态自校 | 脚本 | 能 | 证明「文件写对了」：包结构、域代码、编号、正文零差异 |
| 真机接管验收 | 你在 Word 里点 | **不能** | 证明「你的 Word + Zotero 真的认得这些活引用」 |

> 两者缺一不可：脚本自校只证明文件结构正确，**证明不了软件认它**；只有你在 Word 里 Refresh 一次，才算数。

### 9.2 自动静态自校（脚本 · 照抄命令即可）

用 `config.python` 指定的解释器，在 skill 根目录执行。`<...>` 为 `config.json` 里的路径字段，替换成你的实际绝对路径。

| 时机 | 命令 | 检查什么 | 通过标准 |
|---|---|---|---|
| 生成后、**刷新前**（预填态） | `python scripts/zotero_citation.py --config assets/config.json verify --file <deliver_docx>` | 包部件集合 + 仅 `word/document.xml` 变化且无 custom.xml；域计数；域 JSON 全字段；正文逐段零差异；著录编号连续去重 | 末行 `>>> verify 总结论: 通过` |
| 刷新**之后**（成品态） | `python scripts/zotero_citation.py --config assets/config.json diagnose --file <deliver_docx>` | 域计数、上标数、按 BIBL 域边界取著录段落、残留占位符、URI 匹配 | 逐项人工核对，不判通过/不通过 |
| 只看基线 / 素材 | `inspect` / `material` | 连通性、包结构、占位符、映射覆盖率、著录全文、编号表 | 定位结果与编号表一致 |

> ⚠️ **两套校验器必须隔离**：拿预填态的 `verify` 去量已刷新的成品，必然误报（`pitfalls.md` P6，最常见）。刷新后一律用 `diagnose`。

### 9.3 必须人工在 Word 里做（超详细步骤 · 逐点击照做，无自动化替代）

按顺序走，每一步都写了「你会看到什么」和「不对怎么办」。哪一步看不懂就停在原地，不用硬猜。全程只要点几下鼠标。

#### 阶段 0 · 开始前先认准 4 件事

1. **用哪个文件**：优先打开 `config.json` 里的 `<verify_copy_docx>`（验证副本）。**不要**拿 `<source_docx>` 原件（全程只读），也别一上来就用 `<deliver_docx>` 主交付件 —— 副本验坏了不心疼。
2. **在哪操作**：必须是桌面上**真正的 Microsoft Word / WPS 程序**（装了 Zotero 插件的那个），双击文件打开。右侧预览窗、在线预览、网页版里**没有 Zotero 按钮**，点不了刷新。
3. **确认后台在跑**：Zotero 桌面端已启动、文献库就是 `config.json` 里 `user_id` 指向的那个；`inspect` 已通过（本地 API 可达）。
4. **确认没被占用**：同目录没有以 `~$` 开头的锁文件，目标 docx 没在别的窗口开着。

#### 阶段 1 · 打开文件、找到 Zotero 选项卡

- 双击 `<verify_copy_docx>` 用 Word 打开。
- 看顶部菜单栏，找 **`Zotero`** 选项卡（中文版同名；有些版本藏在「加载项 / Add-ins」里）。
- **找到了** → 进阶段 2。
- **没找到** → **停在这里，别往下点**。多半是插件没加载：确认 Zotero 桌面端在运行、Word 插件已安装、重启 Word 再试；仍不行就回报现象。

#### 阶段 2 · 告诉它用哪种格式（Document Preferences）

- 点 `Zotero` 选项卡里的 **Document Preferences**（中文可能叫「文档偏好设置 / 文档首选项」）。
- 弹出的设置框里找到 **样式 / Style 下拉框**。
- 选中 **D0 已确认**的那个样式（中文默认 GB/T 7714 数字顺序编码；英文默认 APA 7），点 **确定 / OK**。
- **下拉框里有** → 选中即可。
- **下拉框里找不到** → **别乱选相近的凑合，先停**。这往往说明样式没装进 Zotero：Zotero → 设置 / 首选项 → 引用 / Cite → 样式管理器 → 获取或安装对应 `.csl` → 回到 Word 重开此框。这一步也正好帮你确认样式是否装好。
- **为什么必须做**：不做这一步，它不知道引用该长成 `[1][2][3]`、文末该怎么排。本 skill 默认不写文档偏好（C2 / D7 未授权），所以要人工设一次；若你已授权写入 `custom.xml`，这一步可能已预设，可跳过。

#### 阶段 3 · 点刷新（Refresh）

- 点 `Zotero` 选项卡里的 **Refresh**（中文可能是「刷新」或「更新引用和参考文献 / Update Citations and Bibliography」）。
- 等几秒到几十秒（文献多时稍慢）。**期间别手动改正文或文末书目**，也别反复点。
- 若弹出「是否更新 / Update?」→ 点 **是 / Yes**。
- **正常**：正文编号重排、文末参考文献列表整段刷新出来。
- **弹出报错** → 不要自己修，直接跳到**阶段 5 的失败处置**。

#### 阶段 4 · 逐项核对（看三样 + 一个否决项）

| # | 看哪里 | 对了长这样 | 不对劲就记下来 |
|---|---|---|---|
| 1 | 正文每一处引用 | 编号按目标样式渲染（数字顺序编码样式通常是右上角小号上标 `[n]`；若体例要求行内则为 `[n]`），位置在句末标点**之前**；编号从 `[1]` 连续、与正文一一对应，同一文献复用同一号 | 还是普通大小、跑到标点后、跳号 / 重复、冒出多余字符、显示 `{ ADDIN ... }` 之类域代码 |
| 2 | 文章最末尾 | 自动出现**去重**后的参考文献列表，共 **M 条**（M = 唯一文献数，通常 ≤ 引用点数 N），按样式要求编号 / 排序 | 一条都没有 / 不是 M 条 / 顺序乱 / 有重复 |
| 3 | 全程有没有弹警告 | **不弹**任何关于引用的警告 | 出现「未找到条目 / item not found」「样式错误」→ 记下来；「引用已被修改」→ 见否决项 |
| 否决项 | 弹出「引用已被修改 / citation has been modified」 | — | **千万不要点「保留修改 / Keep my changes」**，也别点完继续用；直接停 → 阶段 5 |

> 「引用已被修改」通常说明域里 `plainCitation` 与可见文本不一致（`pitfalls.md` P5 / P6）。点了「保留修改」可能把活引用固化成死文本且不可逆，所以一律先停、先报告。

#### 阶段 5 · 收尾：成功怎么确认、失败怎么办

**三样都对、无警告时**：

1. **再 Refresh 一次**（或换个样式再 Refresh），确认文档不坏、编号能自动重排。
2. 这一步成立，才证明它是「活域」而非静态文本 —— 这是「活引用真能被你的电脑认出来」的**唯一证据**。
3. 回报「三样都对」，进入 S7 交付；此时若要自校，用 `diagnose`（成品态），别用 `verify`。

**任一样不对 / Refresh 失败时（按 C4 / D8 硬停止）**：

- 不改文件、不换成静态定稿、不做 `Unlink Citations`、不反复换样式、不补救式改域、不点「保留修改」。
- 记录：失败现象 + 原始域片段 + 报错全文 + 环境状态（Zotero / Word 版本、样式名、是否刚另存过）。
- 如实回报，等新决策，不自行绕过。

> 补充：刷新后 Zotero 插件会**自行**写入 `docProps/custom.xml`（记住样式所必需，非违规注入，登记保留即可）。这也是为什么刷新后必须用 `diagnose` 而不是 `verify`。
>
> **为什么非要人点**：Zotero 官方本地 API **没有 Word 域写入 / 刷新端点**，后台碰不到 Word 界面按钮。脚本只能把文件写对，认不认得出来得你在 Word 里验 —— 没有任何 headless 官方替代。

## 10. 四项交付物

| # | 交付物 | 必备内容 |
|---|---|---|
| 1 | 修改后的文件（域活文档） | N 个 ITEM 域 + 1 个 BIBL 域 + M 条著录；已 Refresh 成品态 |
| 2 | 完整参考文献列表 | M 条逐字著录 + 编号↔键↔itemKey↔引用位置对照表 + 缺陷加注 + 体例/口径说明 |
| 3 | 未匹配与存疑语句清单 | 未匹配统计（应为 0）、高风险引用点、证据强度双粒度分布、无占位符段落原文、缺陷加注、边界声明 |
| 4 | 统一审核结果 | 一一对应/去重/顺序/格式四项核对、正文完整性、真机 Refresh 结论、约定复核、状态变化、误报说明、残余风险、交付物清单 |

> 走「核实」主线时，交付物 1 缺省（原件不改动），其余三项改为「核对报告 + 存疑清单 + 审核结果」。
>
> **证据强度两种粒度必须分开列**：处级（N 个引用点：直接/部分/仅背景）与键级（M 个唯一键：直接/部分/仅背景），不得混淆。

## 11. 红线、默认约定与停止条件

### 技术事实 / 安全底线（客观限制，不可绕过）

- T1 官方 Local API 无 Word 域写入端点，5-run 域必须自写
- T2 验收必须人工 `Document Preferences` + `Refresh`
- T3 当前脚本不修改 Zotero 文献库、不读取 API key 或其它凭据；不直改 `zotero.sqlite`、不强杀 Zotero
- T4 不打包 CSL 样式文件（许可证不确定）
- T5 5-run 各自独立 `w:r`；`plainCitation` 与可见文本逐字节一致；`itemData` 取 csljson 原样

### 默认约定（可配置，执行前确认）

| # | 约定 | 开关 |
|---|---|---|
| C1 | 原件只读、只替换 `word/document.xml`、正文逐段零差异 | — |
| C2 | 默认不新增 `docProps/custom.xml`、不写 `ZOTERO_PREF_*` | D7 可授权 |
| C3 | 默认只处理已有占位符，无占位符仅登记存疑 | D4 |
| C4 | 默认交付活文档、不做 `Unlink Citations`；Refresh 失败默认硬停止 | D2 / D8 |
| C5 | `title` 默认不强制逐字保留；项目体例要求则设 `title_verbatim=true` | config |
| C6 | 弱证据引用点：列风险、请使用者裁决，不擅自放行/暂停 | D5 |
| C7 | 不编造文献、不勉强匹配；著录缺陷默认原样保留并加注 | config |

> Refresh 之后 Zotero 插件会**自行**写入 `custom.xml` 的 `ZOTERO_PREF_*`（记住样式所必需），这不是违规注入，登记保留即可。

### 停止条件

- 探针或 Refresh 接管失败 → 硬停止、如实报告、等新决策
- 任何需要删文件、改 docx 其它部件、修改 Zotero 文献库、联网下载样式的动作 → 先确认；当前脚本不实现这些动作
- 未明确批准执行卡 → 不动手
- 结论与证据冲突 → 先核实，不擅自改写有依据的表述

## 12. 常见问题 / 误报速查

| 现象 | 先别改文件，先查 |
|---|---|
| 本地 API 连不上 | `HTTP_PROXY` 劫持 → `pitfalls.md` P1 |
| 样式名请求失败 | 查询参数未编码 → P2 |
| API 地址被拒绝 | 仅允许本机 HTTP 回环地址 → P3 |
| 输出路径被拒绝 | 原稿与输出同路径，或两个输出重复 → P4 |
| `[n]` 变上标、校验器全判异常 | 样式 `vertical-align=sup`，正常 → P5 |
| 包部件/SHA 大面积变化 + 含 custom.xml | 是否刚被 Word 另存/Refresh → **P6（最常见）** |
| 著录缺第 1 条 | 是否写死「最后 M 段」且文末多空段 → P6 |
| 可见 `[n]` 多 1 个 | 正则多抓书目首条 → P6 |
| 占位符和句号分属不同 run | 需 `rebuild_paragraph` 重写 run → P7 |
| 期刊名 `&amp;` / 断字 | PDF 抽取缺陷，按 C5/C7 处理 → P8 |
| 作者字段取不到值 | API 用 `firstName/lastName`，csljson 用 `family/given` → P9 |

完整 12 个坑（现象→根因→修法→预防）与反例警示，见 `references/pitfalls.md`。

## 13. 脱敏与可移植性声明

本 skill 是**通用化脱敏版**，可安全用于任何文献写作项目、分发给他人：

- **不含**任何真实文献数据、真实 itemKey、真实作者/期刊/DOI、真实编号表或证据统计数值；
- **不含**任何真实文件路径、账号名、Python 解释器路径、Zotero 数据目录、项目名、日期、会话/计划文件名、项目专属文档名；
- **不含**项目专属裁决（原项目的「顺序编码制·书后统一列表」「行内方括号·句号前」「不写 custom.xml」「title 逐字保留」「Refresh 失败硬停止」等，一律降级为「默认建议 + 执行前询问 / config 开关」）；
- 示例数据一律为 `REF-EXAMPLE-A` / `ITEMKEY01` / `<WORKDIR>` 等**虚构占位符**；
- 所有真实值都由使用者在 `assets/config.json` 提供；`cid_prefix` 默认 `CITE`，请勿改成能反推项目来源的缩写。

**保留的是通用技术资产**（与具体课题无关）：5-run 域构造、CSL-JSON 结构、`users/<LIBRARY_ID>/items/<ITEMKEY>` URI、`ADDIN ZOTERO_BIBL` 跨段落书目域、本地只读 API、两套校验器隔离、故障排查、L1–L4 分级、S1–S7 主干、执行卡/交付物模板。

**如实边界**：适用载体为 Word/WPS `.docx`；纯 LaTeX / Markdown / Google Docs 不适用；最后验收无法全自动，必须人工在 Word 刷新。
