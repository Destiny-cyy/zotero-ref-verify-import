# 工作流：S1–S7 最优路径 · 决策门 · 验收 · 交付物

> 按需加载。`SKILL.md` 是入口，本文件是「怎么一步步走」的详细版。
> 方法纪律：先建地图 → 按需取用 → 每步留痕；写入集中单执行体，审核独立收口。
> 本文件中所有 `N` / `M` / 编号 / 键名均为变量，由使用者的 `config.json` 与素材提供，不含任何固定项目数据。

## 0. 决策门清单（执行前必须先问用户）

| 门 | 问题 | 默认建议（仅兜底，须确认） |
|---|---|---|
| D0 | 用哪种引用格式 / 样式 | 中文→GB/T 7714 顺序编码；英文→APA 7；按**文章语言**，不按被引文献语言 |
| D1 | 顺序编码制 / 著者-出版年制；书后统一列表 / 章节末列表 | 顺序编码制 · 书后统一列表 |
| D2 | 交付形态：域活文档 / 静态定稿 | 域活文档（先跑最小探针验证） |
| D3 | 标注位置与形态（行内方括号 · 句号前 / 上标等） | 由 CSL 样式决定；规划期实测渲染并写入验收基线 |
| D4 | 是否只处理已有 `[REF:]` 占位符 | 只处理已有占位符；无占位符段落仅登记存疑 |
| D5 | 证据偏弱 / 仅背景支持的引用点是否插入 | 列出风险、逐项请用户裁决，不擅自暂停或放行 |
| D6 | 是否授权：补齐条目非 title 元数据 / 安装启用 CSL 样式 | 默认不授权；须显式确认 |
| D7 | 是否授权：新增 `docProps/custom.xml` 写 `ZOTERO_PREF_*` | 默认**不授权**（用户手动在 Word 设样式） |
| D8 | Refresh 验证失败时如何处置 | 默认硬停止、等新决策；不自动退化静态定稿 |

> 以上均为**默认建议**，不是硬性铁律。使用者或用户可逐项调整；调整后仍要在执行卡里写明并等批准。

**注意**：「合规免责」与「默认采用某样式」是两个层面，不是矛盾。若著录确有抽取缺陷、或项目体例文件未标注标准号，删掉免责反而会造出「宣称合规却有缺陷」的新矛盾——保留本体 + 加注对齐。

## 1. S1–S7 最优路径（顺序不可换）

| 步 | 动作 | 输出 · 验收 |
|---|---|---|
| S1 | **只读基线 + 环境探测**：绕代理连通本地 API、三重校验、样式落盘确认、docx 包结构与占位符位置（先 grep 建地图，不通读） | 基线表：无 `~$` 锁、无 custom.xml、无既存域；占位符数量 |
| S2 | **锁定映射**：`REF 键 → itemKey → 编号`，从 API 取真实 `itemData` / `uris`，确认 creators 与 CSL-JSON 字段形态 | 编号表 + N 个可核验 itemKey |
| S3 | **只读定位**：占位符段落 / run / 句号位置，锁定「段落 ↔ 审计 ID ↔ 键 ↔ 编号」，登记无占位符候选段落 | 定位片段 + 存疑候选 |
| S4 | **最小探针**：1 引文域 + 1 书目域 → 静态自校 → **用户 Word 手动设样式并 Refresh 一次接管** | 失败即硬停止，不退化、不写库 |
| S5 | **全量注入**：N 个 ITEM 域 + 1 个跨段落 BIBL 域 + 去重著录 → 严格静态自校（5 项） | 仅 `word/document.xml` 变化；citationID 全唯一 |
| S6 | **用户定稿**：Word 中 `Document Preferences` + `Refresh` | 标注形态与位置、编号连续且与正文一致、文末书目条数、无「引用已被修改」 |
| S7 | **四项交付物 + 独立审核汇总**（审核环节不参与写入） | 一一对应 / 去重 / 顺序 / 格式全通过 |

### 核实主线（文稿已带引用时用）

跳过 S4 / S5 的写入，改为只读：

| 步 | 动作 | 输出 |
|---|---|---|
| V1 | `inspect`：连通性、包结构、占位符残留、映射覆盖率、样式渲染实测 | 基线核对表 |
| V2 | `verify`（预填态）/ `diagnose`（成品态）：按文件状态选对校验器 | 域计数、URI 匹配、著录段落编号、正文差异 |
| V3 | `material`：dump 著录全文 + 编号表 + 存疑候选段落 | 核对素材 |
| V4 | 独立审核：一一对应 / 去重 / 顺序 / 格式 + 证据强度 + 缺陷加注 | 核对报告（不改原件） |

**两套校验器必须隔离**：预填态严格自校用于「刚生成、未 Refresh」；成品态只读诊断用于「已 Refresh」。交叉重跑必然误报（见 `pitfalls.md` P6）。

## 2. 可省的弯路（特定约束才多走，L4 应做成开关）

| 弯路 | 触发条件 | 下次处理 |
|---|---|---|
| W1 自动修改 Zotero 元数据 | 当前版本不支持 | 只登记缺陷，由用户在 Zotero 中修订后重新运行 |
| W2 多子 agent 分块语义核验 | 用户要求「多智能体 + 独立审核」 | 一次定位脚本即可输出分块片段，单执行体合并 |
| W3 探针副本 + 验证副本 + 预填 / 刷新两态 | 手动写域无官方端到端承诺 | 接管机制验证后可单副本 + 一次刷新；验证副本仅备查 |
| W4 对已刷新成品重跑预填态 `verify` | 校验器按预填态写死 | **两套校验器隔离**，不交叉重跑 |
| W5 读取 Zotero 内部数据文件 | 当前版本不需要 | 只通过本机只读 Local API 获取条目；库不符时停止并请用户确认 |

## 3. 验收关卡

### 必须人工在 Word 里验（不可自动化替代）
1. 前置：Zotero 运行中、本地 API 绕代理可达、目标 docx 在 Word 中已关闭、无 `~$` 锁；用户手动在 Document Preferences 设为目标样式（若未授权写偏好）。
2. 执行一次 `Refresh`，看四项：引文形态与位置、编号连续且与正文一致、文末书目条数、有无「未找到条目 / 引用已被修改 / 样式报错」。
3. 再次 Refresh 不破坏文档、可换样式 → 确认是「活域」而非静态文本。
4. 探针 Refresh 接管失败 → 立即停止，记录失败现象 + 原始域片段 + 报错 + 环境状态，等新决策。

### 可自动静态自校（预填态）
- 包部件集合一致、除 `word/document.xml` 外 SHA-256 全不变、无 `docProps/custom.xml` / custom-properties 关系 / Content_Types Override
- 域计数：N 个 ITEM / 1 个 BIBL / begin=separate=end 成对、无落单 `fldChar`
- 每个域 JSON 合法、`schema` 正确、citationID 全唯一、`uris` = `users/<library id>/items/<key>`、`itemData` 含类型、`plainCitation` == 预填可见编号
- 正文逐段纯文本零差异、残留 `[REF:]` 为 0、文末著录编号连续 1..M 且去重

### 成品态只读诊断（Refresh 之后）
不要用预填态校验器复核成品（必然误报）。改用：域计数、`vertAlign=sup` 数、著录段落逐段文本（按 BIBL 域边界取段，**不写死「最后 N 段」**）、残留占位符、URI 与 itemKey 匹配。

### 已知差异，加注不判失败
- numeric 样式 Refresh 后**确定上标** `[n]`；预填态行内、成品态上标，两态分工
- CSL 著录 vs 出版社自定义体例逐字符差异（文献类型标识、DOI 前缀、`等` vs `et al.`、全半角标点）
- 著录首条编号后的空格差异（导出带空格 / Word 悬挂缩进无硬空格）
- Refresh 后 Zotero 插件**自行**写入 `docProps/custom.xml` 的 `ZOTERO_PREF_1`（非我方注入），登记保留
- `Unlink Citations` 不可逆；手动改书目会被下次 Refresh 覆盖
- PDF 抽取缺陷（断字、`&amp;` 双重转义）逐条登记「原样保留 · 未润色」（按 C7 设定）
- 证据偏弱引用点 + 无占位符转述句 → 不得表述为「全部论断已获充分支持」

## 5. 四项交付物模板

| # | 交付物 | 必备内容 |
|---|---|---|
| 1 | 修改后的文件（域活文档） | N 个 ITEM 域 + 1 个 BIBL 域 + M 条著录；已 Refresh 成品态 |
| 2 | 完整参考文献列表 | M 条逐字著录 + 编号 ↔ 键 ↔ itemKey ↔ 引用位置对照表 + 缺陷加注 + 体例 / 口径说明 |
| 3 | 未匹配与存疑语句清单 | 未匹配统计（应为 0）、高风险引用点、证据强度双粒度分布、无占位符段落原文、缺陷加注、边界声明 |
| 4 | 统一审核结果 | 一一对应 / 去重 / 顺序 / 格式四项核对、正文完整性、真机 Refresh 结论、约定复核、状态变化、误报说明、残余风险、交付物清单 |

> 走「核实」主线时，交付物 1 缺省（原件不改动），其余三项改为「核对报告 + 存疑清单 + 审核结果」。

**证据强度两种粒度必须分开列**：处级（N 个引用点：直接 / 部分 / 仅背景）与键级（M 个唯一键：直接 / 部分 / 仅背景），不得混淆。

## 6. 多子 agent 对齐收口

- 并行分块只做**只读**核验（各块语义、对齐核查、经验复盘、前置调研），写入集中由单一执行体完成。
- 收口环节职责：剔除非实质矛盾（不迎合「一定存在矛盾」的预设）、统一口径、合并重复表体、给最终结论。
- 子 agent 报告须带「每步留痕」小节：建立了什么地图、按需读了哪些片段、得出哪些结论。
- 独立审核环节不得参与写入。
